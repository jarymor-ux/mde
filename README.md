# mde

Нативный просмотрщик и редактор Markdown на Rust. Без браузера, JavaScript,
сервера и индексации проекта при запуске.

## Установка и сборки для macOS / Linux

Исходники: [jarymor-ux/mde](https://github.com/jarymor-ux/mde).
Готовые архивы: [GitHub Releases](https://github.com/jarymor-ux/mde/releases).
Автоматические сборки отмечены как **Pre-release**; выбирайте верхнюю успешную
сборку и архив под свой процессор:

| Архив | Платформа |
| --- | --- |
| `mde-macos-arm64.tar.gz` | macOS Apple Silicon (M1 и новее) |
| `mde-macos-x86_64.tar.gz` | macOS Intel |
| `mde-linux-x86_64.tar.gz` | Linux x86_64, Ubuntu 24.04 / glibc 2.39+ |

Linux-архив не предназначен для Alpine/musl или старой glibc: в таком случае
соберите программу из исходников на своей системе. Нужны графическая сессия
X11 или Wayland и OpenGL; это оконное приложение, не терминальный редактор.

### macOS: готовый архив

Распакуйте архив своего процессора. Внутри есть `mde.app`, отдельный исполняемый
файл `mde`, инструкция и примеры. Перетащите `mde.app` в `/Applications` и
откройте его. Сборка подписана ad-hoc, без сертификата Developer ID и notarization.
Если macOS блокирует первый запуск, после попытки открытия разрешите приложение
в **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**.

Для запуска из терминала выполните внутри распакованной папки:

```sh
mkdir -p "$HOME/.local/bin"
install -m 755 mde "$HOME/.local/bin/mde"
export PATH="$HOME/.local/bin:$PATH"
mde notes.md
```

Добавьте строку `export PATH="$HOME/.local/bin:$PATH"` в `~/.zshrc`, если этого
каталога ещё нет в PATH.

### Linux: готовый архив

На Ubuntu 24.04 / Debian с подходящей glibc установите библиотеки выполнения:

```sh
sudo apt-get update
sudo apt-get install -y libxkbcommon0 libwayland-client0 libegl1 libgl1 \
  libxcb-render0 libxcb-shape0 libxcb-xfixes0 libdbus-1-3 \
  xdg-desktop-portal xdg-desktop-portal-gtk zenity
```

На KDE используйте портал своего рабочего стола (`xdg-desktop-portal-kde`).
Портал нужен для системного диалога выбора файлов. На других дистрибутивах
установите эквивалентные пакеты.

```sh
tar -xzf mde-linux-x86_64.tar.gz
cd mde-linux-x86_64
./mde --foreground examples/demo.md

# Установить команду для текущего пользователя:
mkdir -p "$HOME/.local/bin"
install -m 755 mde "$HOME/.local/bin/mde"
export PATH="$HOME/.local/bin:$PATH"
mde notes.md
```

Для постоянного PATH добавьте соответствующую строку в конфигурацию своей оболочки.
Если окно не открывается, запускайте с `--foreground`, чтобы увидеть ошибку.
После скачивания архивов и `SHA256SUMS` контрольные суммы проверяются командой
`sha256sum --check SHA256SUMS` на Linux или `shasum -a 256 --check SHA256SUMS` на
macOS (для полной проверки скачайте все три архива).

### Сборка из исходников

Нужны **Rust 1.95 или новее** и Cargo. Установка Rust:
[официальный rustup](https://rustup.rs/). Рекомендуется текущий stable:

```sh
rustup update stable
rustup default stable
git clone https://github.com/jarymor-ux/mde.git
cd mde
```

На macOS установите Command Line Tools, если они ещё не установлены:

```sh
xcode-select --install
```

На Ubuntu 24.04 перед сборкой установите зависимости:

```sh
sudo apt-get update
sudo apt-get install -y build-essential pkg-config libssl-dev libudev-dev \
  libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev \
  libxkbcommon-dev libwayland-dev libegl1-mesa-dev libgl1-mesa-dev
```

Затем на обеих платформах:

```sh
cargo build --release --locked
./target/release/mde --foreground examples/demo.md

# Или установить команду в ~/.cargo/bin:
cargo install --path . --locked
mde notes.md
```

macOS-приложение можно собрать командой `./scripts/package-macos.sh`.
На Linux ARM64 можно попробовать нативную сборку из исходников; готового ARM64
архива и отдельной проверки этой архитектуры в CI пока нет.

### Автоматические сборки

Workflow [Build and release](https://github.com/jarymor-ux/mde/actions/workflows/release.yml)
запускается при push в `main` или `master`, для pull request в эти ветки и вручную
через **Actions → Build and release → Run workflow**. Основная ветка — `main`.

Каждая платформа проходит `cargo fmt --check`, Clippy с запретом предупреждений,
тесты и `cargo build --release --locked`. На Linux дополнительно проверяется
запуск GUI через Xvfb и программный OpenGL. На macOS собирается `.app`.
После успеха всех трёх сборок push в основную ветку (или ручной запуск на ней)
публикует отдельный GitHub prerelease `build-<номер>.<попытка>-<коммит>` с тремя
архивами и `SHA256SUMS`. Pull request только проверяется, без публикации.
Артефакты Actions хранятся 14 дней; файлы Releases сохраняются до удаления релиза.

## Запуск

```sh
cargo build --release
./target/release/mde examples/demo.md
./target/release/mde one.md two.md three.md
./target/release/mde .
```

Для команды `mde` из любой папки:

```sh
cargo install --path . --locked
mde notes.md
mde "папка с пробелами/заметка.md"
```

`mde` без аргументов открывает стартовый экран. `mde --help` показывает справку.
Аргументы — отдельные пути, фигурные скобки не нужны.

При обычном запуске `mde …` окно работает отдельным процессом, а терминал сразу
возвращает приглашение. Добавлять `&` не требуется. Для отладки и вывода ошибок
можно оставить приложение в терминале: `mde --foreground notes.md`.
Для имён, начинающихся с флагов, используйте `mde -- --help`.

На macOS можно также собрать обычное приложение:

```sh
./scripts/package-macos.sh
open target/mde.app
```

## Шрифт

На вашем Mac используется **Menlo-Regular**, как в kitty: в конфигурации указан
`Fira Code`, но установленный kitty не находит это семейство и выбирает Menlo.
Этот шрифт применяется к интерфейсу, исходному тексту и предпросмотру; файл
`/System/Library/Fonts/Menlo.ttc` читается напрямую без запуска kitty и без поиска
по системному каталогу шрифтов. Настройки kitty не изменяются.

Другой установленный TTF/OTF/TTC можно выбрать без пересборки:

```sh
MDE_FONT_PATH=/path/to/font.ttf mde notes.md
```

Для TTC по умолчанию используется лицо с индексом 0; при необходимости задайте
`MDE_FONT_INDEX`. На других ОС без указанного пути используются встроенные шрифты.

## Возможности

- Скрытый интерфейс по умолчанию: только исходный текст и предпросмотр.
- Управление, темы и выбор вкладки появляются по ⌘/Ctrl Shift P или правой кнопке мыши.
- Обычный интерфейс можно включить по ⌘/Ctrl Shift H; режим запоминается.
- Несколько документов во вкладках; повторное открытие выбирает существующую вкладку.
- Редактор, живой предпросмотр рядом и отдельный режим чтения.
- Подсветка исходного Markdown через Tree-sitter: заголовки, разметка, ссылки,
  выделения и встроенный код; языковая подсветка в блоках Rust, Python,
  JavaScript/JSX, JSON и Bash/Shell.
- Заголовки, списки, цитаты, таблицы, задачи, ссылки и блоки кода.
- Локальные PNG/JPEG, включая относительные пути от папки документа.
- Открытие файлов и папок через системные диалоги и перетаскивание в окно.
- Дерево Markdown-файлов: подкаталоги читаются при раскрытии, рисуются только видимые строки.
- История последних 20 файлов и папок, светлая/тёмная тема, размер шрифта.
- Поиск с переходом к совпадению и замена всех совпадений с учётом регистра.
- Обычные undo/redo и операции с буфером обмена в редакторе.
- Подтверждение при закрытии изменённого документа; отмена сохранения сохраняет правки.
- Сохранение через временный файл и замену; проверка внешних изменений перед записью.

Встроены **Catppuccin Mocha / Latte, Dracula, Nord, Gruvbox Dark / Light,
Tokyo Night, Solarized Dark / Light**. Тема применяется к редактору, предпросмотру
и элементам управления и сохраняется между запусками. Палитры встроены в программу
и не требуют загрузок. Цвета синтаксиса в редакторе также меняются вместе с темой.

Tree-sitter и его грамматики встроены в бинарник, ничего устанавливать отдельно
не нужно. Парсер и запросы создаются при первом непустом тексте в редакторе,
в отдельном потоке. Изменённый документ разбирается в фоне; неизменённый текст
не разбирается повторно при прокрутке, смене темы или размера окна. Старые результаты
не применяются к новой версии текста. Пока идёт разбор, цвета неизменённых частей
документа сохраняются. Для файлов больше 1 MiB подсветка отключена ради скорости.
Разбор через `tree-sitter-highlight` пока не инкрементальный; кэш и фоновый поток
сохраняют отзывчивость интерфейса. Подсветка применяется к исходному тексту;
отрендеренный Markdown сохраняет обычное оформление документа.

В предпросмотре можно писать прямо в документе: нажмите на абзац, чтобы открыть
его разметку на месте. Только текущий блок показывает Markdown и подсветку
Tree-sitter; остальные остаются отрендеренными. Правки сразу меняют исходный текст.
Escape или клик по другому блоку возвращает оформление. Нажмите под последним
блоком, чтобы добавить абзац. ⌘/Ctrl S сохраняет обычный `.md`, ⌘/Ctrl Z и
⌘/Ctrl Shift Z отменяют и возвращают правки, в том числе между блоками.
Это работает и справа в режиме «Вместе». Список, таблица и блок кода редактируются
целиком; связанные сносками блоки открываются вместе, чтобы сохранить их отображение.

Автосохранение включено: через **1 секунду после последней правки** файл записывается
в фоне. У каждой вкладки свой таймер; ввод, undo и правки в рендере заново отсчитывают
секунду. Новому документу сначала нужно выбрать имя через ⌘/Ctrl S.
Запись атомарная, с проверкой внешних изменений. При ошибке правки остаются в памяти,
а автосохранение этого файла приостанавливается до успешного ручного сохранения
или повторного открытия. В простое таймер и поток записи не работают.

В скрытом режиме ⌘/Ctrl B временно открывает дерево проекта. При выборе файла
дерево закрывается. Переключать вкладки можно через Ctrl Tab / Ctrl Shift Tab
либо через окно управления. Название файла и признак несохранённых правок остаются
в системном заголовке окна.

## Клавиши

На macOS используется ⌘, на Windows/Linux — Ctrl.

| Клавиша | Действие |
| --- | --- |
| ⌘/Ctrl N | Новый документ |
| ⌘/Ctrl O | Открыть файлы |
| ⌘/Ctrl Shift O | Открыть папку |
| ⌘/Ctrl S | Сохранить |
| ⌘/Ctrl Shift S | Сохранить как |
| ⌘/Ctrl W | Закрыть вкладку |
| ⌘/Ctrl Q | Закрыть приложение |
| ⌘/Ctrl F | Поиск и замена |
| ⌘/Ctrl Shift P / правая кнопка мыши | Управление, темы и открытые файлы |
| ⌘/Ctrl Shift H | Скрыть/показать весь интерфейс |
| ⌘/Ctrl B | Скрыть/показать боковую панель |
| Ctrl Tab / Ctrl Shift Tab | Следующая / предыдущая вкладка |
| ⌘/Ctrl 1 / 2 / 3 | Редактор / вместе / просмотр |
| Escape | Скрыть поиск / вернуть оформление редактируемого блока |

Разделитель редактора и предпросмотра можно перетаскивать. Средняя кнопка мыши
закрывает вкладку.

## Быстрый старт

Используется `eframe/egui` с OpenGL (`glow`), без `wgpu`. Файлы, проверка путей и
содержимое папок читаются фоновыми потоками после первого кадра. Нет сканирования
вложенных каталогов, сетевых запросов, загрузки предыдущих вкладок или фонового polling.
В простое приложение ждёт событий.

Для документов больше 512 KiB предпросмотр включается отдельной кнопкой: полный
рендеринг Markdown выполняется в UI-потоке и может быть дорогим для больших текстов.
Редактор открывает UTF-8 файлы до 32 MiB. Это обычный текстовый редактор, не редактор
гигабайтных файлов.

Чтобы измерить время от входа в `main` до начала первого UI-кадра:

```sh
MDE_STARTUP_LOG=1 ./target/release/mde --foreground .
```

Это время инициализации приложения; оно не включает загрузку процесса ОС, вывод
кадра монитором или загрузку документа. Первый запуск после перезагрузки может
отличаться из-за дискового кэша и драйвера.

Локальный замер release-сборки на этом Mac (по три новых процесса, кэш ОС
не сбрасывался): медиана от `main` до первого UI-кадра — 143 мс без аргументов,
121 мс с файлом и 121 мс с папкой. От запуска процесса до лога повторные старты
заняли 125–150 мс; первый запуск нового бинарника после сборки — 795 мс,
из которых 199 мс внутри приложения. Это не замер после перезагрузки.
Этот замер сделан до добавления Tree-sitter и фонового CLI-запуска.
Подробные результаты того замера:
`target/startup-benchmark.json`.

С Tree-sitter: медиана от `main` до первого UI-кадра — 141 мс
(три новых процесса с `examples/highlighting.md`, кэш ОС не сбрасывался).
Повторные старты от запуска процесса до лога заняли 131–148 мс; первый запуск
нового бинарника — 1992 мс, из них 191 мс внутри приложения. Загрузка документа
и завершение подсветки в этот замер не входят. Размер бинарника — 12,4 MiB.
Результаты: `target/startup-treesitter.json`.

## Ограничения первой версии

HTML, Mermaid, LaTeX и удалённые изображения не обрабатываются.
Слежения за внешними изменениями и синхронной прокрутки двух панелей пока нет.
Неизвестные языки в блоках кода выделяются единым цветом. При конфликте сохранения используйте «Сохранить как»
с другим именем либо закройте вкладку и откройте свежую версию с диска.

Дерево показывает `.md`, `.markdown`, `.mdown`, `.mkd`; скрытые каталоги,
`node_modules`, `target` и ссылки на каталоги пропускаются. Проверка изменений
на диске выполняется при сохранении, а не в фоне. Атомарная замена сохраняет
разрешения файла и существующие символьные ссылки, но не гарантирует сохранения
расширенных атрибутов или идентичности hard links.

Настройки и история на macOS: `~/Library/Application Support/mde/settings.json`.
На Linux: `$XDG_CONFIG_HOME/mde/settings.json` или `~/.config/mde/settings.json`.
На Windows: `%APPDATA%/mde/settings.json`. Сохраняются при обычном закрытии приложения.

Локально приложение проверено на macOS Apple Silicon. GitHub Actions проверяет
сборку и тесты на macOS ARM64 / Intel и Linux x86_64; на Linux также запускается
GUI через Xvfb. Это не заменяет проверку на каждом рабочем столе и видеодрайвере.
Windows в CI пока не проверяется.
